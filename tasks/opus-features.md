## 단계 0 — 저장소 파악과 뼈대

저장소에는 이미 Fable 이 만든 `src/scene/**`(3D 씬 구현)과 씬 작업에서 임시로 만든 `src/shared/types.ts`, `config.ts` 가 있다. `src/app`, `api`, `db` 는 아직 없다.

1. 코드를 고치기 전에 먼저 읽고 5줄 이내로 요약한다: package.json, 빌드 도구(예: Vite), src/scene 구조, scene-demo.html, README-scene.md, 임시 shared 파일.
2. 기존 빌드 도구와 구조를 따른다. 새 도구로 갈아타지 않는다. 필요한 것이 없을 때만 가벼운 것을 고르고 이유를 적는다.
3. 브랜치 `opus/features` 에서 작업하고 작은 단위로 커밋한다.
4. 앱 뼈대를 만든다: src/app 의 진입점, 화면 전환(입주 / 지도 / 순위 / 꾸미기), 씬 캔버스 연결.
5. Cloudflare 배포 구조를 만든다: Pages(프론트), Workers 또는 Pages Functions(`api/`), D1 데이터베이스 바인딩(wrangler 설정), 스키마와 마이그레이션 `db/migrations/`. D1 연결을 테스트하는 간단한 API 를 만들어 동작을 확인한다. Vercel 과 Neon 은 쓰지 않는다.
6. 내가 직접 해야 하는 일(Cloudflare 계정은 이미 만들었다. wrangler 로그인, D1 데이터베이스 만들기, GitHub 연결 자동 배포 등)은 폰에서 하기 쉽게 한국어로 단계별 안내(README.md)를 쓰고, 필요한 정보를 질문 목록으로 정리해서 먼저 알려준다. 이 채팅 쪽에는 Cloudflare 커넥터가 연결되어 있을 수 있으니, 명령줄로 해야 하는 것과 대시보드에서 하는 것을 구분해서 알려준다.

## 단계 A — 기본 기능 (서버, DB, 화면)

### 전체 그림
- 한 섬에 모두가 같이 산다(공유 섬). 입주하면 집 한 채(마당 포함)와 고양이 한 마리를 받고, 집에 인스타 아이디 이름표가 뜬다.
- 모바일 우선, 세로 화면. 화면 UI는 따뜻하고 둥근 분위기(동물의 숲 같은 아늑함)로 만들되 닌텐도 그림체를 따라 하지 않는다.

### 먼저 할 일
1. src/shared/types.ts, src/shared/config.ts 를 CLAUDE.md 대로 만든다(Fable 이 읽어서 쓴다). 씬 작업에서 만든 임시 파일이 이미 있으면 덮어쓰지 말고 읽고 확장한다(맨 위의 "임시" 표시는 지운다). CLAUDE.md 와 값이 맞는지 확인한다.
2. 3D 씬은 이미 src/scene/index.ts 에 구현되어 있다(기본 인터페이스 10개). 그대로 가져다 쓰고 임시 씬(sceneStub)은 만들지 않는다. 앱은 CLAUDE.md 의 씬 인터페이스 함수만 쓰고 씬 내부 파일은 import 하지 않는다. Fable 이 배치를 동네 방식으로 바꾸는 중일 수 있으니 houseSlot 같은 내부 값에 기대지 않는다.

### 기능
1. 입주 화면
   - 인스타 아이디 입력 + 지역 선택(REGIONS: 17개 시도 + 그 외) → 입주 버튼. 지역은 입주할 때 한 번 정하고 바꾸지 못한다(순위 조작 방지).
   - 아이디 정규화(소문자, 영문/숫자/./_ 만, 최대 30자), 중복 입주 방지.
   - 지금은 아이디 입력만으로 입주하되 "미인증"으로 저장한다. 나중에 인스타 DM 코드 인증(코드를 먼저 보여주고, DM 보낸 사람의 아이디로 연결하는 방식)으로 바꿀 수 있게 claim_codes 구조를 준비한다.
   - 입주하면 브라우저에 로그인 표시(쿠키 또는 localStorage)를 남겨서 다음부터 내 집이 자동으로 열린다.
2. 고양이 입양
   - src/shared/catLook.ts: 인스타 아이디를 해시해서 항상 같은 결과가 나오는 함수 catLook(handle) → { fur, pattern, eyeColor, personality }
   - pattern 은 cheese/black/calico/white/gray/tuxedo, personality 는 짧은 한국어 문구(예: "야식 좋아하는 집사형") 40개 정도를 직접 쓴다.
   - 입양 결과 카드: 고양이 이름(아이디 기반), 털 무늬, 성격 문구, 번지 번호, 지역과 지역 순위(예: "서울 3위 · 우리 지역 1,119마리"). 스크린샷으로 공유하기 좋게 세로 비율로. 고양이 그림은 씬 미리보기가 있으면 쓰고, 없으면 2D 로 간단히 그린다.
3. 지역 대항전 (이 게임의 공유 소재라서 신경 써서 만든다)
   - 지역 순위 화면: "전체 입주 수"와 "이번 주 신규 입주 수" 순위를 탭으로 나눠 막대로 보여준다. 내 지역은 강조한다.
   - 내 지역 순위 카드: "서울 1위 · 우리 지역 1,119마리" 같은 한 줄 요약.
   - 순위에서 지역을 탭하면 씬의 highlightRegion(regionId) 로 강조하고, 다시 탭하면 해제(null).
   - 입주 직후 화면에 "내 지역은 지금 N위, 1위까지 N마리"를 보여준다.
   - 순위 계산은 서버에서 하고 60초 캐시한다.
4. 꾸미기
   - 내 집 마당(6x6 칸)에 아이템 8종을 놓고, 옮기고, 지우고, 회전(0/90/180/270)하는 UI.
   - 지붕 색 선택(12색 정도 팔레트).
   - 저장하면 서버에 올라가고 setYardItems 로 씬에 반영한다.
5. 구경과 예뻐요
   - 집을 탭(onHouseTap)하면 아래에서 올라오는 팝업: 아이디, 번지, 지역, 예뻐요 수, "예뻐요" 버튼.
   - 예뻐요는 하루에 한 집당 1번만(같은 브라우저/IP 기준).
6. 오늘의 특이한 집: 예뻐요가 가장 많은 집을 상단에 보여주고 탭하면 그 집으로 이동(focusHouse), highlightHouse 로 씬에 표시.
7. 상단 HUD: "입주 N마리", "다음 섬까지 N마리"(ZONE_CAPACITY 기준), 내 집 찾기(아이디 검색) 버튼.
8. 창립 주민: 번지 1~100번은 "창립 주민 N번지" 표시.

### 서버와 DB
- 저장소 하나, Cloudflare 배포(Pages 프론트 + Workers API). DB 는 D1(SQLite), wrangler 설정의 바인딩으로 접근한다.
- 테이블
  - (D1 은 SQLite 이므로 boolean 은 integer 0/1 로 쓴다)
  - houses(id, house_no unique, ig_handle unique, verified integer default 0, region, roof_color, likes, created_at)
  - yard_items(house_id, item_type, x, y, rotation)
  - claim_codes(code pk, house_id, used_at): 나중에 인스타 DM 코드 인증용. 지금은 테이블만 만든다.
  - likes_log(house_id, voter_key, day): 하루 1번 제한용
- API
  - GET /api/village: 집 목록을 House 타입으로 반환. 60초 캐시(Cache-Control 또는 Cache API)로 방문자마다 DB 를 호출하지 않게.
  - POST /api/move-in: {handle, region}
  - GET/PUT /api/yard/:houseNo: 마당 아이템과 지붕 색
  - POST /api/like/:houseNo
  - GET /api/regions: 지역별 입주 수, 이번 주 신규 입주 수, 순위
- 모든 쓰기 API 에 IP 기준 레이트 리밋. D1 무료 한도(읽기/쓰기 행 수)를 아끼도록 목록과 순위 조회는 캐시하고, 쓰기는 묶어서 한다.
- 입주자가 없는 빈 집(NPC)은 서버에서 만들지 않는다. 씬이 빈 번지를 NPC 로 채운다. /api/village 응답에 isNpc=true 항목을 넣지 않는다.

### 악용 방지
- 아이디와 문구에 간단한 욕설 필터. 신고 버튼 자리만 만들고 동작은 나중에.

### 단계 A 에서 하지 않는 것
채팅, 상점, 미니게임, 개인 땅 구매, 그림 그리기, 인스타 DM 자동 인증, 사람 캐릭터.

### 단계 A 끝날 때
- README.md 에 Cloudflare 연결 방법(wrangler 로그인, D1 만들기, 배포), 환경 설정, 실행 방법을 한국어로 쓴다.
- 직접 실행해서 입주, 꾸미기, 예뻐요가 오류 없이 되는지 확인하고 CLAUDE.md 의 "현재 상태"를 갱신한다.

## 단계 C — 실시간 서버와 앱 연결 (Fable 의 tasks/03a 와 짝)

씬과는 setRemotePlayers, onLocalMove, getLocalState 로만 주고받는다. 3a 가 아직 없으면 같은 모양의 임시 씬 mock 으로 개발한다.

### 목표
- 내 주변 최대 NEARBY_MAX(20)명만 실시간으로 보이게 한다.
- 미니게임 방 안에서는 참가자가 거리와 상관없이 모두 보이게 한다(방 인프라와 테스트 방만. 미니게임 본체는 만들지 않는다).
- 실시간이 안 되어도 게임은 혼자서 정상 동작한다(단독 모드).

### 서버
- Cloudflare Durable Objects(WebSocket)를 쓴다. 시작 전에 공식 문서(Durable Objects, WebSockets, 한도, 요금)를 읽고 무료 플랜에서 쓸 수 있는 조건(SQLite 방식 등), 하루 요청과 실행 시간 한도, 들어오는 WebSocket 메시지의 요청 환산 비율을 README-realtime.md 에 정리한다. 문서마다 내용이 다르면 최신 문서를 따르고 불확실한 부분을 적는다.
- 연결이 끊기면 클라이언트는 자동 재연결(지수 백오프)과 위치 복구를 한다.
- 월드를 구역(zone) 단위로 나눠 한 구역 = Durable Object 하나로 시작한다. 그 객체가 접속한 유저 위치를 들고 있고, 주변 NEARBY_MAX 명 계산도 객체 안에서 한다. 구역 경계를 넘으면 이웃 구역의 객체로 연결을 옮긴다(끊김 없이 보이게). 별도 공유 저장소는 쓰지 않는다.
- 연결 유지 비용을 줄이는 방식(WebSocket Hibernation API)이 맞는지 공식 문서에서 확인하고 쓴다.
- 무료 한도를 넘어 요청이 실패하면 단독 모드로 돌아가고, 하루 사용량을 로그로 남긴다. 막히면 대안을 제안만 하고 임의로 갈아타지 않는다.
- 접속은 입주한 유저(집이 있는 유저)의 세션 토큰이 있어야 한다.

### 위치 동기화
- 클라이언트는 scene.onLocalMove 값을 MOVE_SEND_HZ(8)로 줄여서 보낸다. 움직임이 없으면 보내지 않는다.
- 서버는 속도와 범위를 검사해서 순간이동이나 비정상 속도는 무시하거나 되돌린다.
- 관심 영역 방식: 월드를 격자 칸으로 나누고, 각 유저에게 NEARBY_RADIUS 안에서 가까운 순으로 최대 NEARBY_MAX 명의 상태만 보낸다. 입장/퇴장은 이벤트로 알린다.
- 전송 데이터는 작게(필요한 값만, 숫자는 반올림). 한 번에 보내는 양과 횟수를 제한해서 사용량과 요금을 아낀다.

### 클라이언트 (src/app/net/realtime.ts)
- 연결, 재연결, 탭이 숨겨지면 전송 중지, 돌아오면 재개.
- 서버에서 받은 주변 유저 목록을 RemotePlayer[] 로 바꿔 scene.setRemotePlayers 에 넘긴다. cat 외형은 서버에서 받은 House 데이터로 채운다.
- 연결 실패나 접속 폭주 시 단독 모드로 넘어가고, 화면에 작게 "혼자 둘러보는 중" 표시.

### 미니게임 방 (인프라만)
- joinRoom(roomId, max = ROOM_MAX), leaveRoom(): 방 안 유저는 거리와 상관없이 모두 서로 보인다. 방 안 메시지는 방 전체에 전달한다.
- 테스트용 방 하나를 만들어서 여러 명이 들어가면 서로 보이는지 확인할 수 있게 한다. 미니게임 규칙은 만들지 않는다.

### 악용 방지와 확인
- 요청 속도 제한, 이름표 욕설 필터, 이상 속도 차단.
- 가짜 접속자 100명이 움직이는 부하 시험 스크립트를 만들고 결과(지연, 서버 사용량 추정)를 README-realtime.md 에 적는다.
- 직접 실행해서 오류가 없는지 확인하고 CLAUDE.md 의 "현재 상태"를 갱신한다.

### 단계 C 에서 하지 않는 것
채팅, 상점, 미니게임 본체, 인스타 DM 자동 인증, 주변 20명을 넘겨서 보이기.

## 단계 D — 보류 목록 (지금은 구현하지 않는다. 나중에 붙이기 쉽게 구조만 열어 둔다)
