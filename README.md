# 고양이섬

인스타 팔로워가 고양이 집을 입양받아 다 같이 사는 3D 섬 웹게임이에요. 세로 화면 모바일 우선이고, 인스타 앱 안의 브라우저에서 열려요.

- 공통 약속(설정, 타입, 씬 함수, 폴더 분담)은 [`CLAUDE.md`](CLAUDE.md) 가 기준이에요.
- 3D 씬 설명은 [`src/scene/README-scene.md`](src/scene/README-scene.md) (Fable 담당).
- 앱, 서버, DB 할 일 목록은 [`tasks/opus-features.md`](tasks/opus-features.md) (Opus 담당).

## 구조 한눈에

```
브라우저 ──▶ Cloudflare Worker "cat-island" (주소 하나)
              ├─ /api/*  → api/index.ts (서버 코드) ──▶ D1 데이터베이스 "cat-island-db"
              └─ 나머지 → dist/ (Vite 로 만든 화면 파일)
```

- **Worker 하나로 화면과 API 를 같이 배포**해요. 같은 주소라서 로그인 쿠키가 인스타 앱 안 브라우저에서도 막히지 않고, 나중에 실시간(Durable Objects)도 이 Worker 에 붙일 수 있어요. Pages 프로젝트는 Durable Object 를 직접 가질 수 없어서 쓰지 않았어요.
- 무료 플랜 기준 D1 한도(2026-11 공식 문서): 하루 읽기 500만 행, 쓰기 10만 행, 저장 5GB. 넘으면 요금이 아니라 그날 자정(한국 시간 오전 9시)까지 쿼리가 실패해요. 그래서 목록과 순위는 캐시해요(단계 A).

### 직접 하실 일: GitHub 연결 자동 배포 (폰 가능)

1. Cloudflare 대시보드 → **Workers & Pages** → **Create application** → **GitHub** → 처음이면 GitHub 로그인과 권한 허용.
2. 저장소 `instaer` 선택.
3. 설정값:
   | 항목 | 값 |
   |---|---|
   | 프로젝트(Worker) 이름 | `cat-island` (반드시 `wrangler.jsonc` 의 `name` 과 같아야 해요) |
   | Git branch (배포 기준 브랜치) | 합친 코드가 있는 브랜치 (아래 "브랜치" 참고) |
   | Build command | `npm run build` |
   | Deploy command | `npx wrangler deploy` |
4. **Save and Deploy** → 끝나면 `https://cat-island.<내계정>.workers.dev` 주소가 생겨요. (이 프로젝트의 실제 주소: `https://cat-island.goyangi-seom.workers.dev`, 2026-11-15 계정 서브도메인을 `goyangi-seom` 으로 변경)
5. 그 주소 뒤에 `/api/health` 를 붙여 열었을 때 `"db":"ok"` 가 보이면 성공이에요.

- 배포하면 실시간용 Durable Object(`RealtimeRoom`)도 같이 만들어져요. 따로 할 일은 없어요.
- 배포가 `ratelimits` 때문에 거절되면 `wrangler.jsonc` 에서 그 부분만 지우고 다시 배포해요(코드는 바인딩이 없어도 동작해요).
- `.dev.vars`(부하 시험 키)는 로컬 전용이에요. 대시보드 환경 변수에 `LOADTEST_KEY` 를 넣지 마세요.

## 내 컴퓨터에서 실행

```bash
npm install
npm run db:migrate:local      # 로컬 DB 에 표 만들기 (처음 한 번)
npm run dev:api               # 터미널 1: 서버(API) http://localhost:8787
npm run dev                   # 터미널 2: 화면 http://localhost:5173 (API 는 8787 로 넘겨줌)
```

- 처음 한 번 가짜 입주자 64명 넣기: `npm run seed:local` (로컬 DB 만. 기존 로컬 데이터는 지워요)
- `http://localhost:5173/` : 앱
- `http://localhost:5173/scene-demo.html` : 3D 씬 확인용 데모 (Fable)
- 실제 배포와 똑같이 보려면 `npm run preview:cf` (빌드 후 Worker 하나로 http://localhost:8787 에서 실행)
- 타입 검사: `npm run typecheck` (화면 코드와 서버 코드 둘 다)
- 로컬 DB 는 `.wrangler/` 폴더에 저장돼요(저장소에 올라가지 않아요).

## API

| 주소 | 하는 일 |
|---|---|
| `GET /api/health` | DB 연결 확인, 집 수 |
| `GET /api/village` | 입주한 집 전체(House), 마당 아이템, 열린 구역 수, 오늘의 특이한 집. 60초 캐시 |
| `GET /api/regions` | 지역별 전체/이번 주 입주 수와 순위. 60초 캐시 |
| `POST /api/move-in` `{handle, region, hideHandle?, cat?, houseNo?}` | 입주 (soft: 팔로우/본인 확인 없음). `houseNo` 는 고른 빈 집(열린 구역 안), 없으면 빈 번지 중 앞 번호. 로그인 쿠키를 남김. IP 당 1분 5번 |
| `GET /api/me` | 이 브라우저의 내 집 |
| `GET /api/auth-info` | 지금 입주 방식 (`off`/`password`/`comment`). 입주 API 는 이 방식이면 `{igId, password, device}` 도 받아요 (2026-11-17) |
| `POST /api/reclaim` `{igId}`, `GET /api/reclaim/:code` | 되찾기: 코드를 내 아이디로 댓글 → 확인되면 그 집으로 로그인 (다른 로그인 끊김) |
| `POST /api/report` `{kind, houseNo?, igId?, contact?, text}` | 신고 (입주 안 해도 됨, IP 하루 10번) |
| `GET/POST /api/wishes` | 소원 비는 곳 (누구나, 하루 3번, 60초 캐시) |
| `GET/POST /api/admin` | 관리자 (헤더 `x-admin-key` = secret `ADMIN_KEY`). 화면은 `#/admin` |
| `GET /api/house/:houseNo` | 그 집 꾸미기 전체: 마당/집 안 자유 배치, 벽지, 바닥, 지붕 그림, 지붕 색. 빈 집(주민 집)은 404 |
| `PUT /api/house/:houseNo` `{yard?, room?, wallpaper?, floor?, roofColor?, roofArt?}` | 내 집만. 보낸 것만 바꿈. 가진 아이템과 내 그림만, 마당 20개/집 안 30개, 벽걸이는 집 안만 |
| `POST /api/drawings` `{pixels, palette}` | 그림 저장 (32x32, 16색, base64 512바이트). 집마다 12장 |
| `GET /api/drawings?ids=a,b` | 그림 여러 장 (60장까지, 하루 캐시. 그림은 바뀌지 않음) |
| `GET /api/me/drawings`, `DELETE /api/drawings/:id` | 내 그림 목록, 지우기 |
| `GET /api/wallet` | 내 츄르, 가진 아이템, 오늘의 퀘스트와 진행도, 도감 |
| `POST /api/shop/buy` `{type}` | 상점에서 아이템 사기 |
| `POST /api/quest/claim` `{id}` | 퀘스트 보상 받기 (오늘의 퀘스트, 셋 다 보너스 `d_all`, 주민 부탁) |
| `POST /api/game/fish` `{catches}` | 낚은 물고기 알리기 (낚시를 마칠 때 모아서 한 번). 가방에 들어감 |
| `POST /api/game/arcade` `{score, ms}` | 생선 받기 한 판 결과 |
| `POST /api/game/visit` `{home}` | 주민 집(섬 모서리) 방문 보상 |
| `POST /api/quest/accept` `{id}` | 주민에게 부탁 받기 (오늘의 부탁, 특별 부탁) |
| `POST /api/game/mine` `{ores:[{id, level}]}` | 동굴에서 캔 광석 (가방에) |
| `POST /api/shop/sell` `{items:{id: 수}}` | 가방의 물고기/광석 팔기 |
| `POST /api/me/rename` `{handle}` | 닉네임(= 고양이 이름) 바꾸기, 500츄르 |
| `POST /api/like/:houseNo` | 예뻐요. 같은 브라우저는 한 집에 하루 1번, 같은 IP 는 5번까지, 내 집 불가 |
| `GET /api/rt/zone/:n`, `/api/rt/room/:id` | 실시간 WebSocket (README-realtime.md) |
| `GET /api/rt/usage/zone/:n` | 그 구역의 오늘 실시간 사용량 |

- 캐시: Worker 메모리 60초 + Cache API. Cache API 는 **내 도메인을 연결했을 때만** 효과가 있어요(workers.dev 에서는 메모리 캐시만). Workers Cache 기능은 켜지 않았어요: 켜면 정적 파일 요청까지 하루 10만 건 무료 요청에 들어가기 때문이에요.
- 쓰기 요청은 같은 주소에서 온 것만 받아요(Origin 검사).

- 촬영 모드 첫 1초 릴스 (2026-11-18, 조회수 200 대책): 촬영 모드 맨 위 "🔥 첫 1초 릴스"(약 14초, 반복 재생용). 검은 화면 없이 빈 집 + 큰 글자 "이 빈 집, 댓글 하나면 당신 거예요" → 하얗게 번쩍하며 빈 집이 내 집(주황 지붕, 치즈 고양이, 이름표 '여기 네 이름')으로 바뀜(영상 안에서만, 끝나면 되돌림) → "★ 창립 주민 처음 100명만, 남은 자리 N"(입주 수로 계산) → "옆집 살 친구한테 보내고 ✈️ 댓글에 '입주'". 바꿔 보이는 집은 가장 최근 입주한 집 옆 빈 집. 나레이션 `src/app/reels/hook-voice.mp3`(ElevenLabs Yeonhee, eleven_v4), 시간은 ElevenLabs 받아쓰기 단어 시간에 맞춤. 근거: 릴스 순위는 시청 시간/끝까지 보기/다시 보기와 DM 보내기(sends)를 크게 본다. 릴스 카드 글자는 `Overlay` 목록(`cinema.ts`)으로 정한다.

## 동접 500명 계산 (2026-11-15, 무료 플랜)

Cloudflare 공식 문서(2026-11) 기준 무료 한도: Durable Objects 요청 **하루 10만 건**(받는 WebSocket 메시지 20개 = 1건, 보내는 메시지는 무료), 실행 시간 하루 13,000 GB-s, Workers 요청 하루 10만 건, D1 쓰기 하루 10만 행.

**바꾼 것**: 내 위치를 1초에 8번 보내던 것을 0.25초마다 찍어 두었다가 **서버가 정한 간격(si)마다 한 번에 묶어** 보내요. 받는 쪽은 si + 0.35초 늦게 되감아 보여 줘서 움직임은 부드러워요. 가만히 있으면 보내지 않아요(연결 유지 ping 은 무료 자동 응답).

- 구역 객체 하나의 연결 상한 300 → 600명.
- 걷지 않을 때 마을 다시 받기 2분 → 5분 (Workers 요청 아끼기).
